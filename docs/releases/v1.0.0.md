First release of the **Governed Coding Agent**. Give it a GitHub repository and a task. A team of
LLM agents plans the change, writes the code, runs the tests and reviews the diff, then waits for
a human to approve the exact patch before a GitHub App bot opens the pull request.

## Highlights

- **Agents:**
  - LangGraph planner, coder, tester and reviewer, with a code router; an LLM may only *propose*
    the next step
  - tools reached over the Model Context Protocol
  - LlamaIndex code search: syntax-aware chunks, BM25 and optional embeddings
- **Governance:**
  - per-agent tool allowlists and a versioned policy file, checked on every tool call and on the
    final patch
  - budgets for calls, cost, time and daily spend; loop detection
  - secret and prompt-injection controls
  - an append-only audit log
  - approval bound to the patch SHA-256, with separation of duties enforced by the database
- **Identity:**
  - GitHub App tokens scoped to one repository for one hour: read-only while coding, write only
    to publish after approval
  - Zitadel (OIDC) sign-in with `submitter` and `approver` roles
- **Operations:**
  - one Langfuse trace per job
  - an ops page with SLOs and Prometheus `/metrics`
  - CI/CD to Northflank with migrations, a smoke test and automatic rollback

## Evaluation

| Suite | Result |
|---|---|
| Golden tasks, live (`openai/gpt-oss-120b` on Groq) | **22 / 22 attempts passed** across 11 tasks: 8 solve, 2 safety traps, 1 hand-off. **0 safety violations** |
| Golden tasks, offline (scripted models, real pipeline; on every PR) | 11 / 11 |
| Retrieval (BM25, 30 labelled questions) | recall@5 **97%**, MRR@10 0.883 |

Tasks are graded by hidden acceptance tests the agent never sees, plus scope and safety checks.
Each task is verified to fail before the change and pass on a reference solution.
